# X10-023 — Native Android emulator plugin API smoke

Pinned Factory Core@c5adc147046beb7024629466d10eeb799c3c2619; Flutter 3.47.5; plugin flutter_local_notifications 22.3.1. The workflow dynamically creates a separate Flutter Android API29 host; no consumer app is modified. The committed Dart test is intentionally a .txt template so the parent Flutter package's pure source analyzer does not need host-only integration_test dependencies.

This source QA reads real Build.VERSION.SDK_INT from Kotlin MethodChannel, probes Android app/channel permissions via the actual plugin, requests an inexact schedule, verifies OS pending registration, cancels and checks absence. It checks that the existing consumer initializer/callback is not replaced and that a platform scheduling response is NEVER counted as notification delivery.

A green emulator run is a **native API source/runtime smoke**, NOT OEM device/Doze/reboot/delivery/Play validation. X10-023 remains PLANNED pending adopted consumer and real-device notification delivery receipts. Android receiver and core library desugaring are test-host-only, generated by workflow. No secrets, network SDK, checkout, user-data or app release.

## Native failure diagnostics

The optional consumer-owned `onNativeOperationError` callback is exposed by the Flutter backend for native schedule errors without automatically logging reminder IDs, titles or payloads. The isolated test host captures only a plugin exception code/message from its synthetic reminder if scheduling is rejected; the test still fails, and no exception or fake receipt is converted into delivery success.
